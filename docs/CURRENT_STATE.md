## Inherited To Replace

- Backend domain/app/infra default builds are narrowed to Wiki-needed modules, while inherited task-tracker compatibility modules and the old SeaORM migration crate remain outside the active Wiki API/server runtime path behind explicit `legacy-tracker` features.
- SQLx persistence currently lives in modular `infra::wiki_postgres` repository implementations as a pragmatic MVP runtime implementation; route handlers call the explicit `shared::wiki_contract::WikiBackendPort`, and all MVP operation slices are separated from the main module behind app-level use cases/repository ports. Production server composition is PostgreSQL-only, while memory mode is explicit test/dev composition. Attachment bytes cross a Wiki-specific storage port instead of direct route-level filesystem access, shared Wiki validation/auth/users/settings/spaces/documents/dossiers/evidence/search/audit helpers and the Wiki runtime context live in the application layer, the contract/settings snapshot live in `shared::wiki_contract`, and the API crate no longer depends directly on Argon2/JWT/SHA hashing crates or production SQLx adapter code for Wiki auth/persistence. PostgreSQL auth register/login/logout records `auth.register`, `auth.login` and `auth.logout` through app/repository boundaries; register and login session writes are transactional with their audit entries. PostgreSQL space create/update/archive/member writes, document draft/publish/archive/move writes, task/phase document link writes, evidence create and attachment upload writes record audit through app/repository boundaries and run write+audit in one transaction.
- Per-space permission checks are implemented in the PostgreSQL runtime and mirrored by the explicit memory test/dev backend for core read/write paths; staged attachment access, claimed file evidence access, attachment-download access, archived-space write rejection, admin-only audit visibility and search authorization semantics are covered by API smoke tests. Deeper repository/API coverage is still needed for less common edge-case combinations.
- Public registration enable/disable behavior is implemented through shared auth config and covered by the API memory smoke; PostgreSQL mode uses the same config gate before creating a user.
- Full generated Wiki frontend operation client is pending backend domain/repository stabilization; DTO schemas are already generated from `openapi/openapi.json`.
