# Фокус после архивирования

После успешного архивирования пространства и документа кнопка действия исчезает:
пространство и документ переходят в режим чтения. Без доступной точки возврата
контролируемый ConfirmDialog оставлял фокус на body. Это воспроизведено на реальном
API с Central Auth: POST вернул 200, повторный GET подтвердил archived.

Wiki использует существующий `fallbackFocusRef` из Base. Для пространства это
строка раскрытого пространства, для документа — его заголовок с `tabIndex=-1`.
Отмена и Escape возвращают фокус на исходную кнопку, пока она доступна. Base
сохраняет блокировку отмены и Escape во время запроса; ошибка остаётся в диалоге.

Изменение принадлежит UI Wiki: только продукт знает, какой элемент остаётся после
архивирования. Общий механизм возврата фокуса остаётся в Base. HTTP, права,
модель данных, миграции и pinned Base не меняются.

Проверки: компонентные регрессии двух успешных ответов с исчезнувшей кнопкой,
отмены и Escape; живые сценарии в трёх темах при 375, 768, 1920 и 2560 px,
клавиатурный фокус, pending и сохранённый статус. Итог: 180 frontend-тестов,
21 браузерная регрессия и 24 живых сценария прошли. Шесть opt-in live fixtures
пропущены. [Снимки и доказательства](../assets/screens/2026-10-04-archive-focus/README.md).
