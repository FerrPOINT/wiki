# Wiki: убрать назначение участников из UI

## Контекст

Central Auth владеет пользовательскими учётками. В интегрированном режиме Wiki
создаёт профиль по `sub` с полным доступом; записи `space_members` не ограничивают
такого пользователя. Страница `/spaces` всё ещё предлагает назначить
`viewer/editor/admin` и удалить участника, хотя эти действия не меняют его права.

## Изменение

- Убрать с `/spaces` форму и список локальных участников, их роли и счётчик.
- Не запрашивать список участников для центрального пользователя при раскрытии
  пространства. Для legacy standalone-профиля оставить проверку членства,
  чтобы прежний space-admin мог изменить пространство. Дерево, создание,
  изменение и архивирование сохранить.
- Таблицу `space_members`, API и CLI не менять: исторические данные и старые
  клиенты остаются совместимыми. Отдельно менять модель доступа без миграции
  данных нельзя.
- Синхронизировать PRD и CURRENT_STATE с актуальным UI-контрактом.

## Проверки

- Unit: после раскрытия пространства нет role/member controls; дерево и
  основные действия работают; архивное пространство остаётся read-only.
- Frontend: codegen, lint, typecheck и полный Vitest.
- Browser на живом стенде: 375/1920/2560, три темы, клавиатура и отсутствие
  неуместного запроса к `/members`.

Последняя проверка отложена до безопасной пересборки: на диске C: менее 0.2 ГБ.
