# Internationalization - Wiki

## 1. Overview

Приложение поддерживает русский (`ru`) и английский (`en`) языки. По умолчанию - русский. Локаль пользователя хранится в профиле и localStorage/cookie.

## 2. Libraries

- Frontend: `react-i18next`, `i18next`, `i18next-http-backend`.
- Backend: статические templates or `fluent` for emails and user-facing errors.

## 3. Namespaces

| Namespace | Content |
|---|---|
| `common` | Buttons, labels, navigation |
| `auth` | Login, register, session messages |
| `spaces` | Space list, settings, members |
| `documents` | Document fields, editor, revisions |
| `dossiers` | Task and phase dossier terms |
| `evidence` | Evidence types and validation messages |
| `errors` | Error codes and messages |


## 6. Usage

```tsx
import { useTranslation } from 'react-i18next'

export function PublishButton() {
  const { t } = useTranslation(['documents'])
  return <button>{t('documents.publish')}</button>
}
```

## 7. Formatting

- Dates use `date-fns` locales.
- Numbers use `Intl.NumberFormat`.
- Server emails use recipient locale.
- API error codes stay stable in English; messages may be localized.

## 8. Testing

- Component tests may use a minimal i18n test config.
- Critical screens should be checked in both `ru` and `en`.
- No raw user-facing strings in mature feature modules after MVP hardening.
